# FMU Simulation + OPC UA + Streamlit

Runs an FMU generated by `fmugen` in containers, exchanging its inputs and outputs through OPC UA, with a Streamlit dashboard to set inputs, launch runs and plot results. It runs with Docker Compose, or on Kubernetes, where [Liqo] can offload the runs to a peered cluster.

1. **OPC UA server**: reads `modelDescription.xml` from the FMU and exposes every input and parameter under `Inputs/` and every output under `Outputs/`.
2. **FMU runner**: runs the FMU with [FMPy]. On each step it reads `Inputs/` from OPC UA, steps the FMU and writes `Outputs/` back. When it finishes, it prints the results as CSV to its log.
3. **Streamlit UI**: shows outputs, edits inputs, starts one runner per run (a container, or a Kubernetes Job), and reads and plots the results from the run's log.

FMI 2 and FMI 3 FMUs both work. FMI 3 arrays become OPC UA arrays and `name[1]..name[n]` CSV columns. Clocks and Binary variables aren't exposed, so models that run code on input clocks (like `examples/kalman`'s `measurement`) only do their per-step part here. Nothing in the stack is specific to one model: every variable name comes from the FMU.

## Layout

```
docker/
├─ Dockerfile            # one image for every component; also builds the FMU
├─ build_fmu.py          # image build step: fmugen build MODEL -> /model/model.fmu
├─ docker-compose.yml    # Docker: opcua-server + streamlit-ui, runs as sibling containers
├─ app/
│  ├─ fmu_io.py          # FMU variables (FMI 2/3) <-> OPC UA types
│  ├─ opcua_server.py
│  ├─ fmu_runner.py
│  └─ streamlit_app.py   # dashboard; run backends: docker | kubernetes
├─ k8s/                  # Kubernetes manifests (kubectl apply -k)
├─ liqo/                 # up.sh / down.sh: two kind clusters peered with Liqo
└─ model/                # optional prebuilt model.fmu (PREBUILT=1)
```

## The image and the model

The build context is the repository root. The image installs fmugen from this repository, downloads UniFMU 0.14.0's Linux CLI, and runs `fmugen build` on the model, which writes `/model/model.fmu`. Because the FMU is built inside the image, its `launch.toml` points at the image's Python (`/opt/venv/bin/python`), and the model's `[model] requirements` are installed next to it. An FMU built on your machine wouldn't work there: it points at your own virtual environment.

| Build argument | Default | Description |
|---|---|---|
| `MODEL` | `examples/psychrometry` | Model folder (with `fmugen.toml`) to build, relative to the repository root |
| `FMUGEN_ARGS` | | Extra `fmugen build` options, e.g. `--fmi 3` |
| `PREBUILT` | `0` | `1`: use `docker/model/model.fmu` instead of building. It must run on Linux: build it with `--vendor --platform manylinux2014_x86_64 --python-version 3.13`, or with `--compile` on Linux. |

## Docker Compose

From `docker/`:

```bash
docker compose up --build
```

To use another model, set `MODEL` when you build:

```bash
MODEL=examples/simple_pid docker compose up --build
```

| Component | Endpoint |
|---|---|
| Streamlit UI | http://localhost:8501 |
| OPC UA server | `opc.tcp://localhost:4841` from the host, `opc.tcp://opcua-server:4840` inside `simnet` |

In the UI:

1. Edit inputs on the right and press **Update** to write them to OPC UA.
2. Set START/STOP/STEP in the sidebar (defaults: the FMU's default experiment) and press **Run**. This starts an `fmu-run-<timestamp>` container on the `simnet` network.
3. Expand the run to see its log. When it finishes, its results appear at the bottom, with a chart and **Download CSV**.

The runner reads inputs from OPC UA on every step, so changes made during a run take effect at the next step. If an FMU only accepts its own step size (`fixed_step`), the runner uses that step size and the STEP field is disabled.

## Kubernetes and Liqo

`k8s/` deploys the same stack in the `fmu-sim` namespace. The UI starts each run as a Job in that namespace, using its own image. The OPC UA server and the UI always stay on the cluster's own nodes. The **Run on** option in the sidebar sets where runs go:

| Run on | Runs are scheduled on |
|---|---|
| `remote` (default, `RUN_PLACEMENT`) | Liqo virtual nodes, i.e. a peered cluster |
| `local` | this cluster's own nodes |
| `any` | either |

With Liqo, the `fmu-sim` namespace is offloaded with `EnforceSameName`. Liqo reflects the `opcua-server` Service into the peered cluster, so a run there connects to `opc.tcp://opcua-server:4840` as it would locally. The UI reads the run's log through the virtual node, and the results come with it. No volume is shared between clusters.

### Try it locally: two kind clusters

Needs Docker, [kind], `kubectl` and [`liqoctl`](https://github.com/liqotech/liqo/releases) (tested with Liqo v1.2.0). From the repository root:

```bash
bash docker/liqo/up.sh
```

This builds the image and creates the kind clusters `fmu-local` and `fmu-remote`. It loads the image into both, installs Liqo in both and peers `fmu-local` → `fmu-remote`. Then it deploys `k8s/` in `fmu-local` and offloads `fmu-sim`. `fmu-remote` then shows up in `fmu-local` as a virtual node. Open the UI with:

```bash
kubectl --kubeconfig ~/.kube/fmu-sim/local.yaml -n fmu-sim port-forward svc/streamlit-ui 8501
```

Runs show up in the UI as `fmu-run-… • succeeded on fmu-remote`. `MODEL=... bash docker/liqo/up.sh` builds another model, and `bash docker/liqo/down.sh` deletes both clusters.

### Your own clusters

1. Build and push the image to a registry every cluster can pull from:

   ```bash
   docker build -f docker/Dockerfile -t <registry>/fmugen-sim:latest .
   ```

   ```bash
   docker push <registry>/fmugen-sim:latest
   ```

2. Set `newName` in `k8s/kustomization.yaml` to `<registry>/fmugen-sim`, then apply it:

   ```bash
   kubectl apply -k docker/k8s
   ```

3. With Liqo installed and peered (`liqoctl peer ...`), offload the namespace:

   ```bash
   liqoctl offload namespace fmu-sim --namespace-mapping-strategy EnforceSameName --pod-offloading-strategy LocalAndRemote
   ```

## Environment variables

**Runner** (set by the UI for each run)

| Variable | Default | Description |
|---|---|---|
| `FMU_PATH` | `/model/model.fmu` | FMU to run |
| `RUN_NAME` | `simulation_outputs` | Name of the run, used for the CSV file |
| `RESULTS_DIR` | unset | If set, also write `<RUN_NAME>.csv` there |
| `START_TIME` / `STOP_TIME` / `STEP_SIZE` | `0` / `10` / `1` | Simulation timing |
| `STEP_DELAY` | `0.5` | Wall-clock pause between steps, in seconds |
| `OPCUA_ENDPOINT` | `opc.tcp://opcua-server:4840` | OPC UA server |
| `OPC_TIMEOUT` | `60` | How long to retry connecting to the OPC UA server, in seconds |
| `RUN_TIMEOUT` | 600 + 2 × steps × `STEP_DELAY` | Seconds after which an unfinished run is stopped (exit status 1), logging what it was doing and printing the results so far. `0`: no limit. Kubernetes Jobs also get `activeDeadlineSeconds`, 300 s later |

**OPC UA server**

| Variable | Default | Description |
|---|---|---|
| `FMU_PATH` | `/model/model.fmu` | FMU whose variables are exposed |
| `OPCUA_BIND_ENDPOINT` | `opc.tcp://0.0.0.0:4840` | Listening endpoint |

**Streamlit UI**

| Variable | Default | Description |
|---|---|---|
| `RUN_BACKEND` | `docker` | `docker`: runs are containers started through the Docker socket. `kubernetes`: runs are Jobs. |
| `OPCUA_ENDPOINT` | `opc.tcp://opcua-server:4840` | OPC UA server, for the UI and the runs |
| `FMU_IMAGE` | `fmugen-sim:latest` (docker); this pod's image (kubernetes) | Image for runs |
| `FMU_CONTAINER_NAME_BASE` | `fmu-run` | Prefix of run names |
| `STEP_DELAY` | `0.5` | Passed to runs |
| `RUN_TIMEOUT` | unset | Passed to runs (unset: the runner's default) |
| `DOCKER_NETWORK` | `simnet` | docker: network that run containers join |
| `RUN_PLACEMENT` | `remote` | kubernetes: default of **Run on** |
| `POD_NAME` | | kubernetes: this pod's name (downward API), to find its image |

## Useful commands

| Action | Command |
|---|---|
| Rebuild the image | `docker compose build --no-cache` |
| Stop and remove | `docker compose down` |
| Logs of a run (Docker) | `docker logs fmu-run-<timestamp>` |
| Remove finished runs (Docker) | `docker rm $(docker ps -aq --filter label=fmugen.run)` |
| Runs and where they ran (Kubernetes) | `kubectl -n fmu-sim get pods -l fmugen.run -o wide` |
| Remove finished runs (Kubernetes) | `kubectl -n fmu-sim delete jobs -l fmugen.run` (Jobs are also removed an hour after they finish) |
